# SimpleMotorController
Simple on/off motor controller for Pololu G2 motor driver

## About
This codebase is for a simple motor controller to be implemented on an STM32 embedded platform interfacing to a Pololu G2 motor driver. The main code is written in C++, along with a set of control/test scripts written in Python to run on a PC host.

## Motor control
The controller provides basic funtionality:
* Enable/disable motor
* Sleep/wake driver
* Ramp motor speed from initial value to final value (either one can be zero)
* Select forward/reverse direction
* Report motor position/speed based on quadrature encoder readings
* Report motor current based on ADC measurements of the current sense output of the G2

## Command interface
The interface to the controller is over UART. There is a simple command/response protocol. The command interface is detailed in `Core/Inc/CommandInterface.h`. The only exception to the command/response model is the log messages generated by the controller. These are broadcast over UART (e.g. they do not require a command from the host to retrieve them).

## Development environment and build instructions
The main STM32 code was developed in STM32CubeIDE. It runs on an STM32L4 procesor (see hardware description below) using v1.17.2 of the STM32CubeL4 Firmware library. The repository contains all of the project files to load this in STM32CubeIDE. The hardware configuration is captured in the STM32CubeMX configuration file `SimpleMotorControl.ioc`. Note that the CubeMX code generation process will update `main.c` rather than `main.cpp`, I'm not sure how to fix that. But generally changes to this should be rare, so I've just worked around this to date. <a href="https://kleinembedded.com/cpp-and-stm32cubemx-code-generation/">This post</a> details in interesting workaround.

There are unit tests for much of the C++ code as well. These are written using the Google Test framework. Building and running the unit tests is managed through CMake. Run the `buildAndRunTests.sh` script to invoke.

There are also a set of Python scripts for interfacing to the motor controller for testing. There are a few unit tests for this as well to validate the message parsing code (handling partial/multiple messages, etc.)

## Hardware
The code is configured to run on an STM32L432KC Nucleo board. The device itself is configured using STM32CubeMX tool which generates the initialization code for all of the device peripherals using the STM32L4 HAL library. Details of connection to the motor driver can be determined from this config file. In brief, here are the main connections:
* TIM1 is used as the counter for the quadrature encoder
* TIM2 is used as the timer for motor drive PWM generation
* TIM6 is used as the timebase for the current sense ADC conversions
* ADC1 channel 12 is used for current sense signal capture (with DMA1 channel 1)
* USART2 is used for host communication (note this is also connected to the USB data lines on the STM32L432KC Nucleo), with DMA1 channel 6 used for Rx
* Several GPIO lines are used:
    * PB0 is used as the DIRECTION output to the G2
    * PB1 is used as the FAULT# input from the G2
    * PB4 is used as the SLEEP# output to the G2
    * PB3 controls the on-board green LED
    * PB5 is used as a hardware flag (e.g it can be toggled to check timing)
